---
title: serverd
description: v2 proof authorization, native billing, leases, and state recovery
---

The server accepts Groth16-authorized requests, reserves nullifiers durably,
and returns Schnorr-signed state transitions after usage settlement.

## Requests and clearance

| Method and path | Interface |
| --- | --- |
| `POST /v2/requests` | `ApiRequestV2` to `RequestResponseV2` |
| `POST /v2/withdraw/clearance` | Withdrawal nullifier to `ClearanceResponseV2` |
| `GET /v2/requests/{client_request_id}` | Recover a prepared/finalized request |
| `GET /v2/nullifiers/{nullifier}` | Recover state by nullifier |

`ApiRequestV2` contains `client_request_id`, `payload`, `payload_hash`,
`public_inputs`, and `proof`. A proof has backend `groth16_bn254` and
base64-encoded Arkworks compressed proof bytes. The server verifies the supplied
public inputs directly and recomputes the canonical payload digest.

A finalized response includes the exact response payload and hash, applied
charge, next commitment, next anchor, server blinding delta, and
`next_state_signature` with `r_x`, `r_y`, and `s` fields. A clearance response
contains the withdrawal nullifier and a Schnorr `signature`. Full shapes live
in `protocol/rust/crates/zkapi-types/src/wire.rs`.

## Native billing and OpenRouter leases

| Method and path | Purpose |
| --- | --- |
| `GET /v2/billing/quote` | Native ETH billing quote |
| `POST /v2/openrouter/leases` | Open a proof-authorized short-lived runtime-key lease |
| `GET /v2/openrouter/leases/{client_request_id}` | Read non-secret lease status |
| `POST /v2/openrouter/leases/{client_request_id}` | Retire a rejected runtime-key lease |
| `POST /v2/openrouter/leases/{client_request_id}/expire` | Expire a native lease |

The live issuance response carries the runtime key once. Recovery and lease
status responses do not return its plaintext. Prompt and response traffic for
direct leases goes between the browser and OpenRouter.

## Operations

`GET /health` reports process health and deployment configuration.
`GET /v1/attestation` publishes deployment and signing-key metadata.
The read-only dashboard uses `/v1/dashboard/summary`, `/v1/dashboard/recent`,
and `/v1/dashboard/events`.

Protocol errors have `error_code`, `error_message`, and `retriable`, plus
optional latest-root, server-time, and retry-delay data. Throttled responses
also carry `Retry-After` when available. A deployment's reverse proxy defines
which private protocol routes the browser may access.
