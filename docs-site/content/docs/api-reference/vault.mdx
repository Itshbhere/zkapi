---
title: ZkApiVault
description: Native ETH deposits, withdrawals, and stale-state challenges
---

`protocol/contracts/src/ZkApiVault.sol` implements protocol version 2 and pins
the Groth16 proof adapter and separate server state/clearance signing keys.
The vault accounts in whole gwei with maximum amount `2^53 - 1`.

| Function | Behavior |
| --- | --- |
| `deposit(commitment, amount, siblings)` | Payable; requires exact `amount * 1 gwei`, inserts the full note leaf |
| `mutualClose(inputs, proof, siblings)` | Verifies withdrawal and clearance, removes the leaf, settles ETH |
| `initiateEscapeWithdrawal(inputs, proof, siblings)` | Verifies withdrawal without clearance, removes the leaf, starts the challenge period |
| `challengeEscapeWithdrawal(noteId, inputs, proof, siblings)` | Verifies an archived request with the matching nullifier and restores the leaf |
| `finalizeEscapeWithdrawal(noteId)` | Settles an uncontested escape after its deadline |
| `claimExpired(noteId, siblings)` | Removes an expired active note and pays the treasury |

Only deposits carry transaction value. Withdrawal statements bind the
network, vault, keys, root, note ID, final balance, destination, nullifier, and
clearance mode. The vault enforces current note state and rejects reused
withdrawal nullifiers.

A close pays the final balance to the chosen destination and the deposit minus
that balance to the treasury. The owner can update the treasury and pause or
unpause new deposits and normal close initiation. Challenge and finalization
paths remain available according to their contract conditions.

`Types.sol` fixes the public input structs. `Groth16ProofAdapter.sol` contains
the verifier for the matching `zkapi-v2-note-bound-v1` setup; changing setup
artifacts requires a compatible verifier and a fresh deployment migration.
