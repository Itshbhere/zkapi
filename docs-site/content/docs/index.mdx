zkAPI lets users fund a private note with native ETH, prove authorization in the
browser, and pay for API usage from a private balance. Each accepted request
consumes one state and returns a fresh server-signed state. Usage settles on
chain when the note closes.

The browser SDK builds proofs using the bundled WASM and proving keys. The
runtime server verifies them, reserves nullifiers, accounts for usage, and
signs state transitions. The indexer supplies Merkle paths, and a separate
challenge service watches for stale escape withdrawals.

Direct OpenRouter leases keep prompt and response traffic between the client
and OpenRouter. The billing server issues a short-lived runtime key and later
settles its usage. The protocol hides private note identity in request proofs;
network and application metadata require separate privacy controls.
